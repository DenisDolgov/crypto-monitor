# feedscan — инвентаризация фидов обменников

CLI-инструмент для одного прохода по списку обменников: для каждого домена он ищет публичный машиночитаемый фид, проверяет его и пишет два отчёта — `reports/feeds.json` и `reports/feeds.md`.

Проект — часть Crypto Monitor. Решения зафиксированы в ADR: [0001](docs/adr/0001-normalized-rate-schema.md) (схема курса и реестр валют), [0002](docs/adr/0002-stack-and-repo-layout.md) (стек и структура), [0003](docs/adr/0003-module-contracts.md) (контракты модулей), [0004](docs/adr/0004-no-bypass-policy.md) (защиты не обходим).

## Требования

- Python 3.11+ (проверено на 3.12)
- только публичные сайты; никаких ключей и партнёрских токенов

## Установка на чистом окружении

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## Запуск

```bash
FEEDSCAN_CONTACT="you@example.com" python -m feedscan --input data/exchangers.csv
```

Отчёты по умолчанию пишутся в `reports/feeds.json` и `reports/feeds.md`. Каталог создаётся автоматически.

`FEEDSCAN_CONTACT` — контакт для `User-Agent` (`feedscan/0.1.0 (+<contact>)`). Без переменной прогон идёт с предупреждением и без контакта; браузерный `User-Agent` не подставляется никогда.

Полезные флаги:

| Флаг | По умолчанию | Смысл |
| --- | --- | --- |
| `--input` | `data/exchangers.csv` | список обменников |
| `--currencies` | `data/currencies.csv` | реестр валют |
| `--out-dir` | `reports` | куда писать отчёты |
| `--limit N` | все | проверить только первые N доменов после сортировки по алфавиту |
| `--contact` | env `FEEDSCAN_CONTACT` | контакт в `User-Agent` |
| `--verbose` | выключен | отладочные строки в stderr |
| `--connect-timeout` | 5 с | таймаут соединения |
| `--timeout` | 15 с | бюджет одной попытки |
| `--retries` | 2 | повторы на сетевые ошибки и 5xx |
| `--per-domain-interval` | 1.0 с | пауза между запросами к домену |
| `--max-bytes` | 5 MiB | лимит сжатого ответа |
| `--max-body-bytes` | 5 MiB | лимит распакованного ответа |
| `--max-redirects` | 3 | редиректы на кандидата |

Коды возврата: `0` — прогон завершён (при любых статусах доменов), `1` — фатальная ошибка записи/окружения, `2` — ошибка входа (CSV, реестр валют, невалидные флаги).

## Формат `data/exchangers.csv`

UTF-8 (BOM допускается), разделитель `,`, первая строка — заголовок.

| Колонка | Обязательна | Правило |
| --- | --- | --- |
| `name` | да | человекочитаемое имя |
| `domain` | да | lowercase, без схемы и пути; ключ обменника в отчёте |
| `url` | да | абсолютный `http(s)` URL главной |
| `source` | да | `bestchange` или `manual` |
| `notes` | да | свободный текст, может быть пустым |

Лишние колонки игнорируются с предупреждением `extra_column:<имя>`. Строка с битым доменом, невалидным URL или неизвестным `source` пропускается и считается в `summary.input_errors`. Дубль домена пропускается с предупреждением `duplicate_domain:`. Отсутствие обязательной колонки или нечитаемый файл — exit 2, отчёты не пишутся.

Текущий `data/exchangers.csv` — ручная выборка из 25 реальных обменников: каталог BestChange на момент сбора отвечал 429/recaptcha, поэтому, согласно решению по MYSP-4, использован ручной seed-список. Для каждого домена в `notes` записано, откуда он взялся и что показала разведка.

## Формат `data/currencies.csv`

Реестр валют (ADR-0001). UTF-8, разделитель `,`.

| Колонка | Правило |
| --- | --- |
| `code` | `^[A-Z0-9]{2,10}$`, уникален |
| `name` | человекочитаемое имя |
| `type` | `fiat`, `crypto` или `metal` |
| `aliases` | идентификаторы из фидов через `\|`: `USDTTRC`, `SberbankRUB` |

Неизвестный идентификатор валюты не угадывается: строка курса отбрасывается с причиной `unmapped_currency:<id>`, а идентификатор попадает в `summary.top_unmapped_currencies`. Неоднозначный алиас, дубль кода или невалидный тип — exit 2.

## Что делает прогон

Порядок для каждого домена (ADR-0003):

1. `robots.txt` — отказ (401/403/429/челлендж) блокирует домен целиком, `Disallow` на путь исключает только этот путь.
2. Главная страница — источник ссылок на фид (`<link rel="alternate" type="application/xml">`, `<a href>` с `xml`/`rates`/`feed`/`export`), только свой домен и поддомены, максимум 10.
3. Четыре типовых пути: `/rates.xml`, `/export/rates.xml`, `/xml/rates.xml`, `/bestchange.xml`.
4. `sitemap.xml` — лениво, только если валидного фида ещё нет; из него берутся ссылки на локальные `.xml`, максимум 10.
5. Общий лимит кандидатов на домен — 25.

Первый валидный фид завершает домен со статусом `ok`. Формат определяется по содержимому, а не по `Content-Type`: `json`, `bestchange_compatible` (root `<rates>` без namespace, `from/to/in/out`), `own_schema` (любой XML с извлекаемыми курсами), `csv`.

## Статусы и причины

| Статус | Когда |
| --- | --- |
| `ok` | найден фид, распознан формат и извлечён хотя бы один курс |
| `not_found` | фида нет: 404/410 по всем кандидатам, нет кандидатов или путь закрыт `robots.txt` |
| `html` | по адресу фида обычная веб-страница (не заглушка защиты) |
| `blocked` | сервер отказал: 401/403/429/451, капча, Cloudflare/JS-челлендж, редирект на логин |
| `error` | технический сбой или невалидный фид: таймаут, DNS, 5xx, превышение лимита, битый XML/JSON, well-formed XML без курсов |

Приоритет, когда валидного фида нет: `blocked > html > error > not_found`. Для `ok` в отчёте есть формат, `format_evidence`, число курсов и 1–2 примера; для остальных — `reason_code` и `reason_detail`.

Well-formed XML без извлекаемых курсов — это `error` / `no_rates_in_feed`, чтобы `ok` означал «фид пригоден».

## Формат `reports/feeds.json`

Верхний уровень: `generated_at`, `config`, `summary`, `domains[]`.

- `summary`: `domains_total`, `status_counts` (все пять статусов, включая нули), `format_counts`, `feeds_ok`, `feeds_with_mvp_directions`, `input_errors`, `dropped_rate_rows`, `top_unmapped_currencies`.
- `domains[]`: `domain`, `name`, `source`, `status`, `reason_code`, `reason_detail`, `format`, `format_evidence`, `final_url`, `http_status`, `content_type`, `encoding`, `gzip`, `size_bytes`, `updated_at`, `rate_count`, `mvp_directions_found`, `examples`, `warnings`, `attempts`, `checked_at`, `duration_ms`, `dropped_rate_rows`, `notes`.

Запись нормализованного курса (ADR-0001): `exchanger_domain`, `base`, `quote`, `rate` (строка с исходной точностью, «сколько quote за 1 base»), `side`, `reserve`, `reserve_derived`, `min_amount`, `max_amount`, `fee_percent`, `updated_at`, `fetched_at`, `direction`, `rate_derived`, `source_url`, `raw` (`sha256`, `size_bytes`, `format`, `encoding`, `http_status`, `content_type`, `gzip`), `warnings`.

Числа — строки, а не `float`: точность курса не теряется. Отсутствие значения — `null`, ноль вместо «нет данных» не подставляется.

## Формат `reports/feeds.md`

Шапка с параметрами прогона → сводка по статусам и форматам → таблица по доменам → блок «Пригодные для MVP» с примерами курсов → блок «Отказы» → «Выводы и следующий шаг».

Отчёты пишутся атомарно (временный файл → `os.replace`) и коммитятся в репозиторий: два прогона на одних данных различаются только `generated_at`, `checked_at` и `duration_ms`.

## Вежливость и пределы

| Параметр | Значение |
| --- | --- |
| частота | не чаще 1 запроса в секунду на домен, включая поддомены, редиректы, `robots.txt` и повторы |
| `Crawl-delay` из `robots.txt` | применяется, если больше нашего интервала |
| таймауты | соединение 5 с, попытка 15 с |
| повторы | до 2 (итого 3 запроса) на таймаут/обрыв/5xx; на 401/403/429/404 и челленджи — ровно один запрос |
| редиректы | до 3, каждый хоп проходит через лимит частоты |
| размер | 5 MiB сжатого и 5 MiB распакованного; при превышении чтение обрывается, тело не сохраняется |
| сжатие | `gzip`; `br`/`deflate`/`zstd` не запрашиваются и считаются ошибкой |
| кодировки | заявленная → UTF-8 → windows-1251, BOM снимается |

Защиты не обходятся: нет браузерного `User-Agent`, `Referer`, headless-браузеров, сервисов капчи, прокси и авторизации. Отказ на `robots.txt` останавливает домен; отказ на конкретном URL исчерпывает только его. Домен уходит в `blocked` с причиной, а не «пробивается».

## Трактовки и отступления от ADR

Всё, что ниже, — осознанные решения реализации; расхождением с ADR считается только непокрытое здесь поведение.

1. **Бюджет запросов на кандидата.** «2 повтора» относятся к сетевым сбоям, редиректы имеют свой лимит. Жёсткий потолок — `retries + 1 + max_redirects` запросов на кандидата (по умолчанию 6), чтобы цепочка из трёх редиректов и трёх таймаутов не давала девять запросов.
2. **DNS-ошибка не повторяется.** Имя, которое не разрешилось, не начнёт разрешаться от повтора; это ещё и сигнал о качестве списка.
3. **`http_4xx`.** ADR-0003 перечисляет 401/403/429/451 и 404/410, но не прочие 4xx (400, 405). Они получают код `http_4xx` и статус `error`; расширение закрытого перечня отмечено в issue MYSP-4.
4. **`ResponseClass.NOT_FOUND`.** Добавлен к пяти классам ADR-0003, чтобы 404/410 не притворялись транспортной ошибкой.
5. **`reserve_currency_id` в `RawRate`.** Без идентификатора нельзя отличить резерв в третьей валюте (тогда `reserve = null` + `reserve_currency_mismatch`) от «валюта не указана».
6. **Один модуль синонимов** (`feedscan/parsers/synonyms.py`) вместо копии в `xml_own.py`: XML, JSON и CSV используют одну таблицу, иначе они разъедутся.
7. **`feedscan/input_csv.py`** — чтение входного CSV отдельным модулем; в раскладке ADR-0002 его не было.
8. **`type = metal`** для `XAU`/`XAG` оставлен (ADR-0001), хотя человек называл только `fiat`/`crypto`.
9. **Единицы измерения в суммах.** В реальном BestChange-совместимом фиде лимиты приходят как `150 USD`, а `tofee` — как `0.0001 BTC`. Такие значения не парсятся в `Decimal` (догадка о валюте запрещена ADR-0001), остаются `null` и получают предупреждение `invalid_amount:min|max|reserve`. `tofee` не маппится в `fee_percent`: это абсолютная комиссия, а не процент. Расширение правил — отдельный ADR.

## Границы

История котировок, хранилище, расписание опроса, алерты и сравнение обменников по выгодности — вне этого инструмента. Оценка юридических условий использования фидов не проводится: фиксируется только техническая доступность. Приватные API, платные ключи и обход защит не поддерживаются.
