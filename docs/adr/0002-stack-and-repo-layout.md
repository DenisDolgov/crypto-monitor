# 0002. Стек, зависимости и структура репозитория

- **Статус:** Proposed
- **Дата:** 2026-11-17
- **Связанные issue:** MYSP-2 (§6, AC-29…AC-32), MYSP-4, MYSP-3
- **Заменяет / заменено:** —

## Контекст

Нужен CLI, который на чистом окружении по README читает CSV, ходит по чужим сайтам с вежливыми ограничениями, разбирает четыре формата и пишет два отчёта. Репозиторий пустой: структура задаётся сейчас и дальше только расширяется. Требования, влияющие на стек: строгий запуск по README (AC-32), тесты без сети (AC-29…AC-31), детерминированные отчёты (AC-12), никаких секретов и обхода защит (AC-27, AC-28).

Ограничение по времени жизни: это инвентаризатор на один прогон, а не сервис. Всё, что тянет за собой фреймворк, хранилище или планировщик, здесь лишнее — но структура должна позволить добавить их позже, не переписывая парсеры.

## Варианты

1. **Python + `requests` + `lxml` + `click`** — привычно, но `requests` не даёт удобного fake-транспорта для «без сети», `lxml` требует отдельной настройки против XXE и расширения сущностей, `click` — ещё одна зависимость ради аргументов.
2. **Python + `httpx` + stdlib `xml.etree` + `argparse`** — гранулярные таймауты и явное управление редиректами, `httpx.MockTransport` позволяет тестировать сетевой слой без monkeypatch и без сокетов, XML-парсер stdlib по умолчанию не раскрывает сущности и не ходит за внешними DTD.
3. **async (`aiohttp`/`asyncio`) + параллельные запросы** — при лимите 1 запрос/сек на домен выигрыша нет (последовательный прогон и так упирается в паузы), зато появляются конкурентные таймеры, блокировки и недетерминизм в тестах.
4. **Scrapy** — готовые politeness/retry, но собственная машинерия ретраев и middleware, которую трудно доказать как «ровно 1 запрос/сек» и «нет обхода защит», плюс тяжёлые зависимости.

Выбран вариант 2.

## Решение: стек

| Компонент | Решение | Почему |
| --- | --- | --- |
| Язык | Python 3.11+ | требование AC-32 проверяется на чистом окружении; 3.11 есть на целевых машинах, даёт нормальные `datetime.UTC` и типизацию |
| Пакеты | `httpx>=0.27,<1` (runtime), `pytest>=8,<9` (dev) | минимум зависимостей; всё остальное — stdlib |
| XML | `xml.etree.ElementTree` | безопасен по умолчанию: не раскрывает объявленные сущности, не тянет внешние DTD; для well-formedness и обхода элементов достаточен |
| JSON/CSV | `json`, `csv` | формат фиксирован, схемных библиотек не нужно |
| CLI | `argparse` | флагов мало, поведение и коды возврата важнее сахара |
| Числа | `decimal.Decimal` (`prec=28`) | см. ADR-0001 |
| HTTP | `httpx` синхронный `Client`, `follow_redirects=False`, `trust_env=False` | ручные редиректы нужны, чтобы каждый хоп прошёл через лимит частоты; `trust_env=False` исключает случайный прокси из окружения |
| Кодировки | stdlib: строгий `utf-8`, `windows-1251`, снятие UTF-8 BOM | цепочка зафиксирована в MYSP-2 §2.2; `charset_normalizer` не нужен и добавил бы недетерминизм |
| Отчёты | stdlib `json` + ручной Markdown | формат задан в MYSP-2 §5.2–5.3 |

Явно **не** добавляем: `lxml`, `pydantic`, `jsonschema`, `click`/`typer`, `requests`, `charset_normalizer`, `tenacity`, `ratelimit`, `scrapy`, `aiohttp`, `pandas`. Каждая из них либо дублирует stdlib, либо приносит политику, которую придётся отдельно доказывать на AC-25/26/28.

## Решение: структура репозитория

```
crypto-monitor/
├── README.md                  # установка, запуск, форматы входа и отчётов
├── pyproject.toml             # метаданные, зависимости, конфиг pytest
├── .gitignore                 # .venv, __pycache__, .pytest_cache; reports/ НЕ игнорируется
├── data/
│   ├── exchangers.csv         # вход: список обменников (владелец — MYSP-4)
│   └── currencies.csv         # реестр валют (см. ADR-0001)
├── reports/
│   ├── feeds.json             # выход прогона, коммитится (AC-33)
│   └── feeds.md
├── feedscan/                  # пакет, запуск `python -m feedscan` без установки пакета в PATH
│   ├── __init__.py            # __version__
│   ├── __main__.py            # `python -m feedscan` → cli.main()
│   ├── cli.py                 # argparse, сборка зависимостей, коды возврата
│   ├── config.py              # RunConfig: дефолты, env, валидация флагов
│   ├── models.py              # dataclasses/enums: все данные, без I/O
│   ├── http_client.py         # вежливый HTTP-клиент (контракт — ADR-0003)
│   ├── decode.py              # байты → текст: gzip, charset-цепочка, BOM
│   ├── robots.py              # robots.txt: загрузка, кэш в рамках прогона, allow/deny
│   ├── discovery.py           # кандидаты на фид: главная, типовые пути, sitemap
│   ├── classify.py            # статус домена и признаки `blocked` (чистые функции)
│   ├── formats.py             # определение формата по содержимому
│   ├── parsers/
│   │   ├── __init__.py        # реестр парсеров
│   │   ├── xml_own.py
│   │   ├── xml_bestchange.py
│   │   ├── json_feed.py
│   │   └── csv_feed.py
│   ├── currencies.py          # загрузка и валидация реестра, resolve()
│   ├── normalize.py           # RawRate → Rate, правила ADR-0001
│   ├── inventory.py           # оркестрация по домену и по прогону
│   └── report.py              # summary, feeds.json, feeds.md, атомарная запись
└── tests/
    ├── conftest.py            # фикстуры: fake transport, clock, tmp_path
    ├── fixtures/              # образцы фидов и негативные случаи
    ├── test_csv_input.py
    ├── test_http_client.py
    ├── test_decode.py
    ├── test_robots.py
    ├── test_discovery.py
    ├── test_classify.py
    ├── test_formats.py
    ├── test_parsers_xml.py
    ├── test_parsers_csv_json.py
    ├── test_normalize.py
    ├── test_currencies.py
    ├── test_inventory.py
    └── test_report.py
```

Правила раскладки:

- пакет лежит в корне (не `src/`), чтобы `python -m feedscan` работал и без install; `pip install -e .` нужен только чтобы поставить `httpx` и получить entry point `feedscan`.
- `data/` — только входные данные, `reports/` — только выход прогона. Код в них не пишет ничего, кроме двух отчётов.
- `tests/fixtures/` — единственный источник истины по форматам для тестов; реальные URL в тестах запрещены (AC-31).
- зависимость направленная: `models` ← остальные; `cli` → `inventory`/`report`/`config`; `http_client` не знает про парсеры; `report` не знает про сеть. Циклов импортов нет.

## Решение: запуск на чистом окружении

README обязан содержать ровно этот путь (и он же проверяется в AC-32):

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
FEEDSCAN_CONTACT="you@example.com" python -m feedscan --input data/exchangers.csv
pytest
```

- Python ниже 3.11 — понятная ошибка при старте (`requires-python = ">=3.11"`), а не загадочный `SyntaxError`.
- `FEEDSCAN_CONTACT` — единственная переменная окружения, которую читает код (контакт в User-Agent). Без неё прогон идёт с предупреждением, браузерный UA не подставляется (AC-27).
- Конфигурационного файла в MVP нет: флаги CLI перекрывают дефолты, больше источников настройки не нужно.

## Решение: конфигурация прогона

Дефолты — нормативные, AC ссылаются на них; переопределение флагом допустимо для тестов и разовых прогонов.

| Параметр | Дефолт | Флаг |
| --- | --- | --- |
| вход | `data/exchangers.csv` | `--input` |
| каталог отчётов | `reports` | `--out-dir` |
| connect timeout | 5 с | `--connect-timeout` |
| таймаут попытки (wall clock) | 15 с | `--timeout` |
| повторов | 2 (итого ≤ 3 попыток) | `--retries` |
| пауза между запросами к домену | 1.0 с | `--per-domain-interval` |
| лимит сжатого тела | 5 MiB | `--max-bytes` |
| лимит распакованного тела | 5 MiB | `--max-body-bytes` |
| редиректов | 3 | `--max-redirects` |
| ограничить прогон первыми N доменами | все | `--limit` |
| контакт в UA | env `FEEDSCAN_CONTACT`, иначе `null` + warning | `--contact` |

Коды возврата (AC MYSP-2 §5.3): `0` — прогон завершён при любых статусах доменов, `1` — фатальная ошибка записи/окружения, `2` — ошибка входа (CSV, реестр валют, невалидные флаги).

## Решение: детерминизм и тесты

- Время берётся из инъектируемого `Clock` (`now() -> datetime`), в тестах — фиксированное. Без этого AC-12 невыполним.
- Порядок доменов в отчёте — алфавитный по `domain`, независимо от порядка строк в CSV: два прогона на разных машинах дают одинаковый файл (кроме трёх временных полей).
- Сеть в тестах отсутствует физически: транспорт подменяется `httpx.MockTransport`, домены в фикстурах — только локальные имена (`exchanger-a.test`, `exchanger-b.test`), никаких реальных хостов и IP.
- Тесты парсеров и нормализации — на файлах из `tests/fixtures/`; тесты оркестрации — на fake transport, который отдаёт заранее заданные ответы по URL и считает запросы и интервалы (это и есть проверка AC-25/26).
- `pytest` настраивается в `pyproject.toml`: `testpaths = ["tests"]`, без плагинов, требующих сети.

## Последствия

- Зависимостей две, обе ставятся на чистом окружении; «запуск по README» действительно воспроизводим.
- Отчёты коммитятся в репозиторий (AC-33) — `.gitignore` не должен их прятать, а прогон обязан быть детерминированным, иначе каждый коммит отчёта будет шумным диффом.
- `httpx` навязывает свою модель таймаутов; ручные редиректы и ручная распаковка gzip означают больше кода в `http_client`, зато лимиты размера и частота проверяемы построчно.
- Без `lxml` нет XPath: парсеры ходят по дереву явно. Для фиксированных форматов это плюс — меньше магии, но для «дикого» XML придётся писать обход аккуратно.
- CI не добавляется: issue этого не требует, а GitHub Actions без запроса — лишняя инфраструктура. Когда появится, workflow будет вызывать те же команды из README.
- Появляется файл `data/currencies.csv`, которого нет в AC MYSP-4: реестр валют — следствие решения «все направления», и его seed-наполнение входит в реализацию (иначе ни один фид не нормализуется). Это расширение объёма MYSP-4, а не скрытая работа.

## Что осталось открытым

- Нужен ли `--keep-raw` (ADR-0001) — не решается здесь.
- Формат `data/exchangers.csv` описан в MYSP-2 §5.1; его наполнение — зона MYSP-4, здесь зафиксировано только имя и место.
- Кто владеет `data/currencies.csv` после MVP: реестр растёт при появлении новых валют в фидах, правки идут через ревью; отдельного владельца пока нет.
